# ALINA BEAUTY ASSISTANT — Telegram-бот

Python 3.10+ · aiogram 3 · SQLite. Языки: RU / ES / EN.

## Запуск

1. Создайте бота в @BotFather → получите токен.
2. Узнайте Telegram ID владельца (напишите боту `/id` после первого запуска или @userinfobot).
3. Переменные окружения (см. `.env.example`):
   - `BOT_TOKEN` — токен
   - `OWNER_ID` — ID владельца (главный админ, единственный, кто управляет админами)
   - `DB_PATH` — путь к базе, **обязательно на постоянном диске**, например `/data/bot.db`
4. Локально: `pip install -r requirements.txt && python main.py`

### Railway (рекомендуется)
New Project → Deploy from GitHub (залейте папку в репозиторий) → Variables: `BOT_TOKEN`, `OWNER_ID`, `DB_PATH=/data/bot.db` →
**Volumes → Add Volume → Mount path `/data`**. Start command: `python main.py` (есть `Procfile`).

### Render
Нужен **Background Worker** + **Disk** (смонтировать в `/data`, `DB_PATH=/data/bot.db`). Это платные функции.
Бесплатный Web Service засыпает и не имеет диска — для бота не подходит (заявки и подписчики пропадут при перезапуске).
Если всё же используете Web Service — задайте `PORT` (бот поднимет health-check).

> Без постоянного диска база стирается при каждом деплое: пропадут подписчики, заявки и правки цен.

## Админ-панель (`/admin` или кнопка «⚙️ Админ-панель» в меню)
- **Заявки** — статусы: новая / в обработке / подтверждена / перенесена / отменена. Подтверждение и перенос — с вводом даты/времени; клиент получает сообщение автоматически. Можно написать клиенту через бота.
- **Услуги и цены** — цена, «от», старая цена («вместо»), названия и описания RU/ES/EN, скрыть/показать, добавить/удалить услугу.
- **Тексты** — приветствие, контакты, часы работы, акции, FAQ, адрес, шаблоны сообщений клиенту и др.
- **Портфолио и отзывы** — загрузка/удаление фото.
- **Подписчики** — статистика, список, экспорт CSV.
- **Рассылка** — всем или по языку, текст или фото с подписью, предпросмотр, отчёт.
- **Администраторы** (только владелец) — приглашение по одноразовой ссылке или по Telegram ID, удаление.

Новые заявки приходят всем администраторам с кнопками статусов.

## Правила безопасности из ТЗ (как реализовано)
- Запись **никогда не подтверждается автоматически** — только после действия админа.
- Цены, помеченные в ТЗ как «подтвердить», стоят как **неподтверждённые** и показываются клиентам как «уточните у администратора». Админ вводит цену → она автоматически становится подтверждённой.
- Медицинские описания (ботокс, филлеры) загружены с пометкой **«требует проверки»** и **клиентам не показываются**, пока специалист не одобрит их («✅ Одобрить описание»).
- Любой текст можно пометить «требует проверки» — он скрывается от клиентов.
- Показаны дисклеймер и предупреждение о тревожных симптомах после инъекций (112).
- Перед записью — согласие на обработку персональных данных; ссылка на политику задаётся в «Тексты → Ссылка на политику конфиденциальности».
- В заявке не собираются медицинские данные.
